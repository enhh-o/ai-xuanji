# AI 问询与 Cloudflare 部署设计

## 目标

将当前“玄机解盘”的本地演示聊天升级为可调用模型的问询功能，并为迁移到 Cloudflare Workers 与用户自有 GitHub 仓库做好准备。真实 API 密钥不得出现在浏览器、Git 历史或公开网站构建产物中。

## 范围

- 前端聊天框请求同源 `POST /api/chat`，展示加载、成功与可理解的失败提示。
- Worker 校验输入后，调用用户配置的 OpenAI 兼容聊天接口；当前可配置为火山引擎方舟。
- 将当前排盘生成的八字、紫微与大运摘要作为结构化上下文随请求发送；系统提示词固定在服务端，明确其只能给出命理倾向与现实建议，不把推断表述为确定事实。
- 创建不含密钥的 `.env.example`，并在项目根目录创建已被 `.gitignore` 忽略的 `.env` 空白模板。
- 补充 Cloudflare 环境变量配置说明，并在用户提供空仓库链接及授权后推送代码到其 GitHub 仓库。

## 非目标

- 不保存聊天记录、不引入账户、数据库或支付功能。
- 不在本次实现模型流式输出、长记忆、文件上传或多模型路由。
- 不替用户填写、读取、提交或上传真实 API Key。
- 不在未获得 GitHub 仓库链接和授权前向任何用户仓库推送代码。

## 架构

```text
浏览器聊天框
  └─ POST /api/chat（问题 + 当前命盘摘要 + 最近有限轮对话）
       └─ Cloudflare Worker
            ├─ 输入校验、长度限制、服务端系统提示词
            ├─ 读取 AI_API_KEY / AI_CHAT_COMPLETIONS_URL / AI_MODEL
            └─ 调用模型服务商的 chat/completions 接口
                 └─ 返回精简的文本回答给浏览器
```

Worker 是唯一可读取 `AI_API_KEY` 的位置。浏览器只知道同源接口 `/api/chat`，不会接触服务商 Key 或完整授权请求。

## 配置契约

`.env.example` 与 `.env` 使用同一组通用字段：

```env
# 模型服务的 API 密钥；真实值只填写在 .env 或 Cloudflare Secret 中
AI_API_KEY=

# 完整聊天接口地址，例如服务商提供的 /chat/completions 地址
AI_CHAT_COMPLETIONS_URL=

# 服务商要求的模型标识
AI_MODEL=
```

当前用户本机可填写：

```env
AI_CHAT_COMPLETIONS_URL=https://ark.cn-beijing.volces.com/api/v3/chat/completions
AI_MODEL=deepseek-v4-pro-ga-260813
```

`AI_API_KEY` 留空时，接口必须返回可理解的“尚未配置模型服务”提示，不能返回底层异常内容。

## API 契约

### `POST /api/chat`

请求：

```ts
{
  question: string;
  chartContext: {
    bazi: string[];
    ziweiSummary: string;
    fortuneSummary: string;
    gender: "女" | "男";
  };
  history: Array<{ role: "user" | "assistant"; text: string }>;
}
```

限制：问题去除首尾空白后必须为 1–800 字；历史仅保留最近 6 条；上下文由当前页面已有排盘结果构建，长度受限。

成功响应：

```ts
{ answer: string }
```

失败响应：

```ts
{ error: "面向用户的中文提示" }
```

错误分类：`400` 输入不合法、`503` 未配置模型、`502` 上游模型服务不可用、`504` 超时。服务端日志可以保留技术详情，但响应不得包含密钥、完整上游地址或原始错误栈。

## 模型消息与命理边界

- 系统提示词放在 Worker 中，要求先总结后分析、使用通俗中文，并注明分析为文化与个人反思参考，避免把人生事件写成确定预言。
- 命盘关系、旺衰与大运信息来自当前本地排盘逻辑；模型负责根据问题组织解读，不负责重新编造盘面。
- 服务端同时传入“关键关系存在不等于必然应事”“大运定阶段、流年作触发”的约束，避免模型把单一合冲写成确定事件。

## 前端交互

- 发送时禁用发送按钮并显示“正在整理命盘信息…”。
- 成功后追加模型回答；失败后显示中文提示，保留输入文字，以便用户修改后重试。
- 仍可通过已有建议问题触发聊天。
- 演示版标签改为“模型服务未配置”或“已连接模型”，由接口可用性决定，不假装在线。

## 安全与隐私

- `.env*` 已被忽略；`.env.example` 不含真实值。
- Cloudflare 部署时将 `AI_API_KEY` 配置为 Secret；接口地址与模型名配置为普通环境变量即可。
- 不记录用户出生信息与聊天内容到数据库；请求只在本次模型调用中使用。
- 生产阶段仍需补充限流与滥用防护；本期 MVP 至少限制单条输入、历史长度和超时。

## 测试与验收

1. 单元测试：缺少配置、空问题、超长问题、上游超时、正常上游响应。
2. 前端测试：发送时请求 `/api/chat`，接口失败时显示中文提示并保留用户文本。
3. 构建测试：现有渲染测试与生产构建均通过。
4. 密钥检查：Git 暂存区与构建输出不包含 `AI_API_KEY` 的真实值。
5. 部署后手工验收：Cloudflare 环境变量配置完成后，用一条建议问题验证真实回答；未配置 Key 时应显示明确引导而非白屏。

## GitHub 与 Cloudflare 交付顺序

1. 实现、测试并提交本地代码；`.env` 不进入提交。
2. 用户创建空的私有 GitHub 仓库并提供仓库链接；用户通过 GitHub 授权或提供仅限该仓库内容读写权限的临时令牌。
3. 推送代码到用户仓库。
4. 用户在 Cloudflare 创建/连接 Worker 项目，并在其仪表盘配置三个环境变量，其中 API Key 用 Secret 保存。
5. 部署并进行真实问答验收。
