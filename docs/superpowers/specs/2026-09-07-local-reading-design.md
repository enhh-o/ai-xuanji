# 本地综合命理解读设计

日期：2026-09-07。状态：用户已批准，本地综合复核主流程已实施；细则实际覆盖及未覆盖范围见 ../../local-analysis-coverage.md，不能将本设计的目标列表当成全部已实现。

## 1. 目标与已确认方向

用户已确认：全盘复核与综合解读不调用 AI，尽量细致补全本地规则；根据原局、格局、调候与岁运，分别输出性格、事业、财富、感情的总结、依据和建议。AI 聊天继续独立提供追问。

推荐采用浏览器内运行的 TypeScript 规则模块，复用现有历法与紫微排盘，不增加服务器、数据库或 Python 运行依赖。全部分析按同一份结果渲染，修正目前“顶部复核、下方初判、转折提示各用一套逻辑”的风险。

替代方案：仅翻译现有 Python 粗筛更快，但不足以解决格局、喜忌和岁运问题；把 Python 部署为新服务会增加维护和联网依赖，当前不采用。

本地规则可重复运行、可核对，不等于命理预测获得科学验证。不得宣称算法测得真实人格、财富等级或必然婚期。

## 2. 当前代码审查依据

- `app/page.tsx` 的 `buildAnalysis` 仍用月支五行、生扶存在与否等粗筛判强弱；强弱不明时仍返回固定的食伤、财星候选。
- `usefulStatus` 始终为“待复核”；`buildLuck` 的策略因此统一为“稳进”，并未完成各运取用裁决。
- 调候仅有冬月、夏月提示，未使用十干十二月专项表。
- 综合复核按钮仍调用 `sendQuestion`，复核内容与聊天状态耦合。
- 已有精确起运区间字段，但年度窗口对交运年采取跳过处理；需分段而不是整年遗漏。
- 目前真太阳时为近似校正，历史夏令时、全球时区和节气边界不能在本次分析模块内冒充已经解决。

## 3. 规则来源与采用边界

以已安装 yueyuan v1.8 的 SKILL、`规则约束.md`、`mingli_rules.py`、`references/patterns.md`、`references/biange.md`、`references/analysis-checklist.md` 和 `references/quxiang-mode.md` 为主要规则来源。

源码已明确：Python 的四项旺衰指标与月令取格只是粗筛，不是完整专家系统。本项目需要新增条件判断，而非复制粗筛后改名“全盘复核”。

引用的 120 项调候表须逐项保留天干顺序、注释、来源版本与“待核对”状态；数组与注释冲突时记录冲突，不擅自凭记忆修改，也不默取数组首项作为最终用神。保留 MIT 版权许可及改编说明。

默认采用子平取象口径。盲派只作有来源的补充，不与子平共用一个隐藏加权分数。未经实现和验证的规则注明未覆盖，不能用泛化模板伪装已分析。

## 4. 输入、输出与模块职责

输入：历法引擎的四柱、藏干、十神、出生日期、性别、月令长生状态、起运和大运起止；可选真实紫微盘；明确的分析日期和所选年份范围。

不读取姓名、聊天内容或用户经历来改变基础命盘判断。分析函数不访问网络、当前时间或页面状态，日期由调用方显式传入。

输出统一的结构化报告：

- 规则版本、输入指纹、采用口径、计算日期、覆盖范围。
- 原局事实与每条关系的具体位置。
- 旺衰、主格与兼格、成败救应、病药、调候、六维取用及冲突。
- 性格、事业、财富、感情四份领域结论。
- 当前大运、逐段岁运作用、候选变化窗口。
- 未覆盖项、具体待辨条件与修订记录。

每个判断含：规则编号、状态（支持／不支持／待辨／不适用）、支持事实、反向事实、通俗总结、建议。支持与反证引用事实编号，而不是重复拼接不一致文案。

拟增加 `app/analysis/`：

- `types.ts`：输入、事实、判断、领域报告和岁运窗口类型。
- `facts.ts`：干支位置、十神、透藏、根气、关系标准化与去重。
- `natal.ts`：旺衰、月令取格、特殊格局候选。
- `patterns.ts`：组合、成败救应与病药条件。
- `climate-data.ts`、`climate.ts`：原表与专项条件评估。
- `useful.ts`：六维裁决，保留分歧，禁止简单投票。
- `timing.ts`：大运、流年及交界分段，领域触发链。
- `domains.ts`：四领域总结、来源与可执行建议。
- `index.ts`：按依赖顺序生成报告及一致性检查。

页面只适配现有数据并展示结果；不再承担全部判断。不得顺带重写无关 UI、聊天后端或部署配置。

## 5. 原局事实与根气

逐字保留柱位和天干／地支／藏干位置。藏干分别映射十神，不将午中丁己合称一个十神。

根气分别登记同干根、同五行异阴阳的支持、本气／中气／余气及所在位置。遵循本 Skill 的同干根气口径，同元素支持不能冒充该天干的同干根。

登记得令、得地、得生、得助，以及泄耗制约。遇冲、合等只先记录关系；“被冲”不自动删除根气，“相合”不自动变更五行。

合、冲、刑、害／穿、破、三合、三会分别识别。害与穿共用事实编号，不算两个独立信号；半合、半会不能代替完整合局或会局。争合与多处同字使用明确位置避免重叠和误指。

本次保持现有关系图外观：天干关系在线上方、地支关系在线下方；图与详细解读引用同一批事实。

## 6. 旺衰、格局、病药

### 旺衰

月令背景 → 根气深浅与状态 → 透干生扶 → 制耗结构 → 完整会合及制化复核。输出偏弱、中和偏弱、中和、中和偏旺、偏旺或具体待辨，不使用无标定的百分比。

将“得令但无根”“失令但有根有生助”“印成势但财官也有力”“根气受冲但未证实拔根”设置为独立测试分支。印多不能直接推出身旺或印为忌。

### 月令与格局

月支藏干本气优先核对透干；本气未透再查中余气；记录多神同透，不以日干自身充当外部透出。基础格与成格分开，不能因为取到“正官格”就判事业好。

建禄与阳干羊刃采用已验证历法字段，不把所有帝旺都判羊刃。普通、从势、专旺、化气使用独立判断路径。特殊格局条件不齐只报候选与缺口，不统一反转喜忌。

### 成败救应与组合

覆盖规则表列出的正官、七杀、正偏财、正偏印、食神、伤官、建禄、羊刃的成格条件、破坏条件和救应。

优先细化食神制杀、杀印相生、伤官佩印、羊刃驾杀、财官印流通；逐项检查参与天干是否透出、根气能否支持、是否受合绊或克制。仅同见两个十神只能输出组合候选。

病药覆盖：枭神夺食、财坏印、伤官见官、比劫夺财、财多身弱、印多为病、官杀混杂、七杀无制、杀旺印弱、刃旺无制，以及合绊妨碍生克的候选。母多灭子、拔根、合化等缺少可明确操作条件时保留待辨，不能靠次数阈值强判。

印星参与命名前先校验其作用：印为忌时不得仍称伤官佩印。正印克伤官不称枭神夺食。无根无印仍须先检查制化自救，不能自动判从。

## 7. 调候与六维取用

专项表优先；显示候选天干在原局透出、暗藏、同干根气及受制状态。没有出现的调候神应显示“原局未见”，不能写成已经发挥作用。

寒暖燥湿不能仅凭出生季节决定；极端调候优先必须有全局条件，检查身极弱不从、从势、专旺、化气和调候神无根等例外。无法判定是否极端则不触发优先覆盖。

六维分别输出扶抑、格局、调候、病药、通关、变格建议与条件。先确认状态，再按规则优先级裁决；禁止计票、取并集或“身弱就喜印比”。

显式检查财生官护印、印旺用财损印、官印相生、食伤制杀等反例。允许同一五行在不同结构中作用不同，不能把干支喜忌变成五行固定善恶。

来源冲突和判断分歧藏在可展开依据中，不在主界面堆英文等级。内部不确定程度仅描述规则分歧，不代表预测正确率；无相反路线时不机械标高，也不所有盘都“待复核”。

## 8. 原局、大运、流年联动

原局是背景；大运先判断新增或改变哪些结构；流年再检查如何作用于该运和原局。不重复把原局内部关系作为大运新增关系。

大运重新检查根气支持、用神条件、组合形成／受阻／救应以及方向变化，而不是只比较该运五行是否在喜神数组中。

流年按立春区间，使用现有历法库计算边界；交运年按真实交运时刻拆两段评估。记录双方区间，不统一略过，也不将全年归入某一步运。

转折定义改为“传统规则下，多层条件同时改变某领域原有状态的候选窗口”，与一般主题年区分。各事件分别建立原局背景、运层条件、年度触发和限制条件；同一关系不能重复计数。

- 感情：按输入性别的默认伴侣星口径，结合日支；区分星透、得根、合日主、宫位变化及破坏／救应。只有宫动不写婚期；不推断用户已婚、离异或伴侣不忠。
- 事业：官杀、印、食伤与实际取用、月柱引动、运年制化共同判断；不能“见官就是升职”。
- 财富：财星与任财、来源、比劫分配、护财与运年支持共同判断；不输出收益保证或财富数额。
- 全盘：识别具体受影响的结构和领域，不靠把事业、感情分数相加制造“重大转折”。

成人事业、婚恋窗口从满十八岁后的区间起算；儿童不写职业晋升、结婚。一般环境变化使用适龄表述，不将成人规则换个名字冒充学业预测。

默认未来十年，保留已有全范围入口。满足条件的年份按时间呈现并可折叠展开，不按固定数量凑满或截为两条；没有强窗口时提供一般主题与明确的未满足条件，而非暗示人生不会变化。

## 9. 四领域总结与紫微补充

每领域默认呈现：一句总结、主要机会或难点、两条针对性建议；展开后查看原局依据、大运改变、近期流年、反向条件和规则来源。

性格先看已成立结构，再看透出且受根气／月令支持的十神，最多两个主倾向加一个修饰。虚透、受制、印为喜忌等实际状态必须改变文案；不再以十神计数最大者生成固定标签。

事业总结区分专业输出、组织协作、责任压力和自主经营的条件；财富区分机会、承接、留存与分配；感情区分表达、相处、边界与阶段变化。建议作为现实中的行动选项，不声称穿某颜色或补某元素可以改变命运。

紫微仅使用真实盘的相关宫位、主星、亮度、本命四化及三方对宫；不得将本命四化称为大限／流年四化。已有静态星曜文案须受宫位和状态约束；没有可核对的组合规则则只补充盘面事实，不编造相互印证。

两盘同向可以说明传统解读同向，不当作独立科学证据；不同向分开解释，不能隐藏矛盾。紫微未就绪时八字报告照常可用，宫位加载成功后仅更新紫微补充，不改动八字事实。

## 10. 页面与聊天接入

排盘后本地自动生成报告；原“开始全盘复核”改为查看／收起详细依据，不发送模型请求，不受聊天加载或限流影响。保持暖色主题和五行纯色。

移除综合解读中的发送模型提示、聊天错误和模型等待状态。四领域初判卡、喜忌、运势解读、关键窗口统一来自本地报告，避免新旧判断并列冲突。

AI 聊天保留独立按钮和发送行为；仅用户发送问题时调用模型。上下文可携带本地报告的版本、摘要和关键依据，明确这是规则推论而非事实。模型回答不自动覆写本地结果。

换人、换日期或切换性别即重新生成；迟到的旧盘数据不得混入新报告。报告默认仅在页面内存，不新增持久化个人资料。

## 11. 验收与测试

采用先写失败测试、再实现的方式。至少覆盖：

1. 120 项调候表完整、候选顺序一致、来源状态保留；数组／注释冲突不被隐藏。
2. 每个藏干有独立十神，同干根与同类支持区分，根受冲不等于拔根。
3. 月令取格透干顺序、兼格、阴干不误判阳刃。
4. 枭神夺食与正印克伤官不混称；印为忌时佩印不成立。
5. 食神制杀成立与食神无根／被制的成对反例；有自救不直接判从。
6. 调候专项优先，五条例外，未见之神不算已到位。
7. 财官反例能改变默认扶抑方向；六维冲突不取简单并集。
8. 同一盘各处强弱、喜忌和根气一致，结论均引用现存事实。
9. 立春、起运前、交运前后、生日边界分别测试；未成年无成人事业／婚恋事件。
10. 仅宫动、仅星透与星宫运年联合条件有不同结果；不为每盘强凑婚期。
11. 紫微缺失不生成示例；本命四化不冒充动态四化。
12. 改变关键输入时对应依据与结论变化；仅改变姓名不得改变判断。
13. 禁止网络请求时本地综合分析仍能完成；AI 聊天仍独立工作。
14. 当前既有测试、类型检查、完整构建通过；不以源码包含某词作为行为正确的主要证据。

新增测试盘只用于验证规则程序行为，不冒称真实命例或预测验证。保存每类规则的正例、反例与未覆盖项；准确率评估需要后续独立资料，不能从单元测试通过率推导。

## 12. 交付边界与实施顺序

依次实现：事实标准化 → 原局与格局条件 → 调候与六维裁决 → 岁运联动 → 四领域报告 → 替换页面旧读法 → 回归验证及规则覆盖文档。

每一阶段保留可验证产物，但最终不能只交付查表或撤掉 AI 按钮。未实现规则必须在覆盖文档中明确区分“已实现”“条件待辨”“未覆盖”。

不在此轮增加医学、生死、灾祸、财富数额预测，也不建设自动反推时辰、后验学习系统或完整紫微动态盘。既有排盘边界须如实说明。本轮不推送 GitHub、不部署、不调用收费模型、不读取或输出密钥。
