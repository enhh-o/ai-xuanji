# 本地综合解读 Implementation Plan

> 执行方式：当前会话顺序实施，使用 TDD 和 verification-before-completion；保持现有预览目录与未提交改动，不发布。

**Goal:** 将已经确认的本地分析方案落地为可追溯、无模型调用的综合报告。
**Architecture:** 纯函数标准化原局事实，依次计算结构、组合、调候与取用，再计算岁运区间和领域报告。页面及聊天摘要消费同一结果。
**Tech Stack:** TypeScript、React、lunar-javascript、Node test。
**Spec:** docs/superpowers/specs/2026-09-07-local-reading-design.md

## Global Constraints

- 不调用收费模型测试、不推送、不部署；不改变原有 UI 风格。
- 保留调候数据源及 MIT 许可，待核对条目不能作为绝对依据。
- 结构关系存在与合化成立分离，特殊格局条件不足必须保留。
- 测试只验证程序行为，不证明命理预测准确。

## 执行清单

- [x] 事实与规则：建立 app/analysis 的类型、透藏根气和关系模块；测试同干根、冲而未拔根、取格透干顺序。
- [x] 原局裁决：实现旺衰、格局、制化与病药条件检查，以及六维取用；成格和候选分开。测试印为忌不称佩印、食神制杀反例、从格自救闸门。
- [x] 调候：从已检查的 mingli_rules.py 原样迁移 120 项和注释，记录版本冲突、候选位置与缺失；测试全表与五条例外。
- [x] 岁运：使用真实立春、大运与成年时刻取区间交集，重新评估新增作用并分别输出星、宫与岁运链；测试交运、立春、十八岁边界。
- [x] 统一接入：页面总评、喜忌和岁运使用同一报告，替换模型复核为本地详情，聊天仅按明确发送调用；测试无网络情况下报告生成及数据隔离。
- [x] 验证交付：运行 pnpm run typecheck、pnpm test、git diff --check，并对本地预览做 HTTP 检查；更新覆盖清单，明确实现和未覆盖范围。

每项遵循：先在 tests/local-analysis.test.mjs 添加对应行为断言 → node --test 观察失败 → 实现 → 重新运行并回归。反例使用合成结构盘，不引用为真实命例。

## 本轮验收备注

本地报告主流程和上述条件检查已经接入，原设计的全部传统规则变体并未穷尽。具体条件性实现、未覆盖项以 `docs/local-analysis-coverage.md` 为准，不能将勾选解读为完整命理专家系统认证。

额外反例修正：受冲根不先删除再判从；单一五合不直接等于合绊；财官印可通关时不机械按财坏印。旧测试中的非法丙巳合成柱改为合法丙戌；壬申增加藏干后含戊土支持，预期从单向制耗改为作用交织，并断言对应藏干依据。
